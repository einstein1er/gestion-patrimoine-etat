# Projet de gestion du patrimoine de l’État
## 1. Objectif
Développer une application web permettant de recenser, localiser,
affecter et suivre les biens de l’État, leur historique et leur maintenance.
## 2. Contraintes du brief
- Backend : Laravel.
- Base de données : PostgreSQL.
- Conteneurisation : Docker.
- Architecture : microservices.
- Conception : UML et maquettes Figma.
- Code source : dépôt GitHub avec README détaillé.
- Documentation : guide d’utilisation et fiche technique.
- Déploiement : plateforme de démonstration sur un hébergement gratuit.
## 3. Utilisateurs envisagés
- Administrateur : gère les comptes, rôles et paramètres.
- Gestionnaire du patrimoine : enregistre les biens et suit leurs affectations.
- Responsable de service : consulte les biens de son périmètre et formule des demandes.
- Technicien : traite les interventions qui lui sont affectées.
- Auditeur : consulte les données et l’historique selon ses droits.
Ces rôles et leurs permissions restent à préciser.
## 4. Périmètre initial envisagé
- Authentification et autorisations.
- Gestion des biens, catégories, services et localisations.
- Affectations et historique des mouvements.
- Demandes de maintenance et suivi des interventions.
- Tableau de bord.
## 5. Fonctionnalités avancées envisagées
- QR code par bien.
- Validation des transferts.
- Maintenance préventive.
- Journal d’audit.
- Import CSV avec aperçu et rapport d’erreurs.
## 6. Décisions restant à valider
- Catégories de biens incluses dans la première version.
- Technologie frontend.
- Découpage des microservices et échanges entre eux.
- Authentification et règles d’accès.
- Outil de modélisation UML.
- Hébergement gratuit compatible avec l’architecture.
- Priorités de réalisation selon le temps disponible.
## 7. État du projet
Ce document décrit un périmètre proposé.
Il ne signifie pas que les fonctionnalités sont déjà développées.
